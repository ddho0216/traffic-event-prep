# 백본 트래픽 관제 · 이벤트 대비 (버전 2)

IDC 관제 2년 3개월 경험에서 손으로 반복하던 일을 자동화해 본 포트폴리오입니다.
**모든 데이터(센터, 고객사, 회선, 수치, 월드컵 일정, 서버실 온도, 방문자, 장비 출력)는 지어낸 가상 데이터입니다.** 센터 이름(분당·서초·구로·안산)은 지명만 빌린 가상 센터이며 실제 센터의 설계·장비·수치가 아닙니다. 실제 회사·고객사 자료와 실제 월드컵 일정은 쓰지 않았습니다.

배포 주소: https://traffic-event-prep.vercel.app/

## 하는 일
| 탭 | 자동화한 수작업 |
| --- | --- |
| 관제 | 5분 간격 in/out 그래프 8개(고객사별 보기), 마우스를 올리면 값 표시, 80% 경고, 버튼으로 CSV 내려받기, 맨 위 종 모양 알림(확인 필요 건수 배지, 경고 이력·내 업무. 경기와 겹치는 알림은 기본 숨김). 첫 화면은 모니터만. "현재로" 버튼, "시나리오" 4가지(평일 오후 7시·트래픽 급감·트래픽 폭주·서버 온도 변화: 몇 초 안에 상황과 조치가 흘러가는 안내 재생) |
| 월간 자료 | 대상 월(기본: 지난달)의 1일~말일 한 달치가 기본이고, 다른 기간은 시작일·끝나는 날을 직접 골라서 고객사 요청 자료(회선별 5분 CSV + 최대·최소·평균·95%값 요약)를 zip과 메일 초안으로 |
| 이벤트 대비 | 월드컵 경기 7개: 예상 초과 링크 찾기 → 분산 제안 → "이쪽으로 보내겠습니다" 통보문 → 사후 예상 vs 실제 |
| 서버실 | 센터 4곳의 서버실(랙 20개·서버 80대)의 입구 온도와 LED 상태, 온도 경고 이력, 육안점검 기록, 온도 기록·점검표 CSV, 서버를 누르면 연결된 스위치 가상 터미널, ⚙ 설정 패널(온도 기준·그래프 범위·이동 단위·시간 재생) |
| 방문 신청 | 방문 신청 메일에서 항목 추출 → 기존/신규 방문자 구분 → 등록 → 회신 초안 |
| 장비 터미널 | 제조사(Juniper·Cisco·Huawei)를 고르면 그 제조사 장비만 나오고, 광값·CRC 확인 명령을 가상 장비에서 연습 (실제 장비 접속 없음). 설계도(장비표·연결표)에서 장비와 포트를 만든다 |

## 직접 겪은 것과 가정한 것
- 직접 겪은 것: 5분 간격 그래프 확인, 데이터 내려받아 고객사에 전달, 서버 온도 체크, 육안점검(불빛 보고 판단), 방문 신청 등록, 광값·CRC 확인, 경기·행사 때 사전 연락과 분산, 새벽 DDoS 확인
- **가정한 것**
  - 하이드레이션 타임(전·후반 약 3분, 트래픽 약 20% 감소): 퇴사 후 생긴 규칙이라 직접 겪지 못했고 수치도 임의입니다.
  - 경기 시청 곡선, 배율, 고객사-회선 연결, 95%값 포함 여부
  - 랙 입구 온도 기준(27·30·33°C), 서버 LED 의미, 냉각 이상 사례

## 실행
```bash
python3 gen_data.py          # data/*.csv 생성 (seed 고정)
python3 export_site_data.py  # site/data.js 생성
cd site && python3 -m http.server 8000   # http://localhost:8000
```

## 테스트
```bash
python3 -m unittest discover -s tests -v   # 데이터 규칙 + 파이썬 교차 검증 + 정답표 최신 여부 (pandas, node 필요)
node --test "tests/*.test.js"              # 탐지 정확도(정답표 비교) + 규칙 경계값 (Node 18 이상)
node tests/report.js                       # 정답표 vs 탐지 결과를 표로 출력 (재현율·오탐)
node tests/sweep.js                        # 탐지 기준값을 바꿔 가며 놓침·오탐 변화 보기
node tests/smoke.js                        # 화면 점검 (playwright 필요, 주소를 넘기면 배포본도 점검)
python3 tests/make_truth.py                # 정답표(tests/ground_truth.json, docs/ground_truth.md) 다시 만들기
```

- 정답표: 데이터에 일부러 심은 사건이 정답입니다. 사람이 읽는 표는 `docs/ground_truth.md`입니다.
- 교차 검증: 사이트의 탐지(JavaScript)를 파이썬으로 따로 다시 계산해 같은 결과가 나오는지 비교합니다.
- 설계도 일관성: 장비·포트·연결이 서로 맞는지, 그래프 링크 8개가 모두 설계도에 있는지 확인합니다.
- 규칙 경계값: 79.9%/80.0%, 2.99배/3.0배, 10분/15분 같은 기준 바로 위·아래를 확인합니다.

## 구조
- `gen_data.py`: 가짜 데이터 생성 (평소 곡선 + 월드컵 7경기 + 새벽 급증 + 급감 2건 + 서버실 온도)
- `export_site_data.py`: CSV를 사이트용 데이터로 변환
- `site/lib.js`: 탐지·판정 규칙 (화면 코드 없음, 터미널에서도 실행)
- `site/topology.js`: 설계도 (센터·장비·랙·회선의 기준. 가상 장비 36대와 연결표 50여 건. 서초에 대형 중앙 백본 2대, 센터 4개(분당·서초·구로·안산)가 거기에 이중화로 붙음, CDN 연결은 여러 곳. 분당 장비가 가장 많음. Juniper(FS) 18대, Cisco(FR) 4대, Huawei(AS) 14대)
- `site/`: 정적 웹페이지 (외부 라이브러리 없음)
- `tests/`, `docs/`: 데이터 규칙 검사, 탐지 정확도 시험, 화면 점검, 정답표

## 알아 둘 점
- 사후 정리의 "실제"는 분산 조치 전 가상 데이터 기준입니다.
- 내려받는 파일 이름은 영문입니다. 한글 이름이면 일부 브라우저에서 이름이 사라지는 것을 확인했습니다.
- 생성해 둔 데이터는 14일치(10/19~11/01)입니다. 월간 자료의 10/19 이전 구간(지난달 앞부분, 긴 기간 등)은 같은 규칙(평소 하루 모양)으로 화면에서 즉석에서 만든 가상 값이며, 경기·사고는 없는 평소 기록입니다.
- 이름 규칙은 `IDC_<센터 코드>_<종류><번호>`입니다. 센터 코드는 B 분당, S 서초, G 구로, A 안산이고, 종류는 FS = Juniper, FR = Cisco, AS = Huawei 계열입니다. 그래프 회선은 `IDC_B_FS1_UP1`처럼 장비와 용도가 보이게 지었습니다. 랙은 `IDC_B_R03`, 서버는 `IDC_B_R03_S2`처럼 같은 규칙입니다. FS·FR·AS가 무슨 약자인지는 확인하지 못했습니다.
- **센터 동기화**: 맨 위 "센터" 선택(전체·분당·서초·구로·안산)은 **관제와 서버실에서만** 보이고, 두 화면이 같은 센터로 맞춰집니다. 서버실에서만 센터 버튼 옆에 랙·서버 수가 보입니다. 터미널·설계도는 센터 선택과 상관없이 전체 장비를 보여 줍니다. 선택은 브라우저에 저장됩니다. 센터마다 보이는 그래프·랙 이름이 모두 그 센터 소속이고 설계도와 일치하는지 시험(`tests/topology.test.js`, `tests/smoke.js`)으로 확인합니다.
- 고객사 13곳(전부 가상)과 회선 배정은 제가 임의로 정한 것입니다. 모든 회선에 고객사가 하나 이상 붙어 있고, 그래프 제목은 고객사가 3곳 이상이면 "외 N곳"으로 줄여 보입니다.
- 장비 분포(Juniper 주력, Cisco 4대, 분당에 장비 다수, 서초가 가장 큼)와 설계도는 은호님 기억을 바탕으로 제가 만든 초안이며 현장과 다를 수 있습니다.
- 경기 중 in이 평소의 3배로 오르는 것은 알림으로 봅니다(은호님 판단: 간당간당한 수준). 경기 겹침 표시는 원인 표시입니다.
- 정답표 시험은 "깨끗한" 가짜 데이터(평소 잡음 2%)로 하므로, 탐지 기준이 느슨해도 통과합니다 (`node tests/sweep.js`로 확인). 애매한 케이스(완만한 감소, 짧은 하락, 잡음이 큰 날 등)를 추가해야 기준의 좋고 나쁨을 가릴 수 있습니다.
- 방문 등록·육안점검 기록은 브라우저(localStorage)에만 저장되며 서버로 보내지 않습니다.
