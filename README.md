# 백본 트래픽 관제 · 이벤트 대비 (버전 2)

IDC 관제 2년 3개월 경험에서 손으로 반복하던 일을 자동화해 본 포트폴리오입니다.
**모든 데이터(센터, 고객사, 회선, 수치, 월드컵 일정, 서버실 온도, 방문자, 장비 출력)는 지어낸 가상 데이터입니다.** 실제 회사·고객사 자료와 실제 월드컵 일정은 쓰지 않았습니다.

배포 주소: https://traffic-event-prep.vercel.app/

## 하는 일
| 탭 | 자동화한 수작업 |
| --- | --- |
| 관제 | 5분 간격 in/out 그래프 8개(고객사별 보기), 마우스를 올리면 값 표시, 80% 경고, 버튼으로 CSV 내려받기, 경고 이력(경기 일정과 겹치는지 표시) |
| 월간 자료 | 고객사 요청 자료(회선별 5분 CSV + 최대·최소·평균·95%값 요약)를 zip과 메일 초안으로 |
| 이벤트 대비 | 월드컵 경기 7개: 예상 초과 링크 찾기 → 분산 제안 → "이쪽으로 보내겠습니다" 통보문 → 사후 예상 vs 실제 |
| 서버실 | 랙 6개·서버 24대의 입구 온도와 LED 상태, 온도 경고 이력, 육안점검 기록, 온도 기록·점검표 CSV |
| 방문 신청 | 방문 신청 메일에서 항목 추출 → 기존/신규 방문자 구분 → 등록 → 회신 초안 |
| 장비 터미널 | 광값·CRC 확인 명령을 가상 장비에서 연습 (실제 장비 접속 없음) |

## 직접 겪은 것과 가정한 것
- 직접 겪은 것: 5분 간격 그래프 확인, 데이터 내려받아 고객사에 전달, 서버 온도 체크, 육안점검(불빛 보고 판단), 방문 신청 등록, 광값·CRC 확인, 경기·행사 때 사전 연락과 분산, 새벽 DDoS 확인
- **가정한 것**
  - 하이드레이션 타임(전·후반 약 3분, 트래픽 약 20% 감소): 퇴사 후 생긴 규칙이라 직접 겪지 못했고 수치도 임의입니다.
  - 경기 시청 곡선, 배율, 고객사-회선 연결, 95%값 포함 여부
  - 랙 입구 온도 기준(27·30·33°C), 서버 LED 의미, 냉각 이상 사례

## 실행
```bash
python3 gen_data.py          # data/*.csv 생성 (seed 고정)
python3 export_site_data.py  # site/data.js 생성
cd site && python3 -m http.server 8000   # http://localhost:8000
```

## 테스트
```bash
python3 -m unittest discover -s tests -v   # 데이터 규칙 14개 (pandas 필요)
node tests/smoke.js                        # 화면 점검 16개 (playwright 필요, 주소를 넘기면 배포본도 점검)
```

## 구조
- `gen_data.py`: 가짜 데이터 생성 (평소 곡선 + 월드컵 7경기 + 새벽 급증 + 서버실 온도)
- `export_site_data.py`: CSV를 사이트용 데이터로 변환
- `site/`: 정적 웹페이지 (외부 라이브러리 없음)
- `tests/`: 데이터 규칙 검사, 화면 점검

## 알아 둘 점
- 사후 정리의 "실제"는 분산 조치 전 가상 데이터 기준입니다.
- 내려받는 파일 이름은 영문입니다. 한글 이름이면 일부 브라우저에서 이름이 사라지는 것을 확인했습니다.
- 방문 등록·육안점검 기록은 브라우저(localStorage)에만 저장되며 서버로 보내지 않습니다.
