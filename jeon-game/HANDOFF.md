## 0. 먼저 읽을 것 (가장 중요한 규칙)

1. **사용자가 준 그림을 그대로 쓴다.** 제가 코드로 새로 그린 그림으로 대체하지 말 것.

2. **배포 전에 반드시 목업(스크린샷)을 보여주고 승인을 받는다.** 승인 없이 `main`에 올리지 말 것.
3. **누끼(배경 제거)는 깨끗하게.** 회색 배경이 외곽선 바깥에 남으면 안 됩니다. `handoff-tools/peel.py`, `olclip.py`를 쓰세요.
4. **흐리면 안 된다.** 캔버스는 2880×1800(논리 960×600의 3배)입니다. 스캔라인·과한 비네팅 효과는 뺐습니다.
5. **사용자가 "하라"고 한 것과 "물어본 것"을 구분한다.** 확인 질문에는 먼저 "됩니다/안 됩니다"로 답하고, 실행 요청은 바로 한다.
6. 응답은 **존댓말**, 짧은 문장·목록. 확신 수준을 **[확실]/[가능성 높음]/[추측]**으로 표시. 제가 만든 값(숫자, 대사, 레시피)은 "제가 만든 것"이라고 밝힐 것.
7. 사용자는 비전공자이고 코딩은 AI가 합니다. 설계·결정·테스트는 사용자가 합니다. 선택지는 2~3개로 줄여서 추천을 앞에 두세요.
8. 이미지는 AI가 **새 메시지로 첨부된 것만** 파일로 읽을 수 있습니다. 작업 도중 끼어든 이미지는 저장되지 않은 적이 있으니, 안 보이면 "새 메시지로 다시 첨부해 달라"고 요청하세요.
9. 개인 정보(이메일, 직업 등)는 외부 서비스·저장소에 쓰지 않습니다.

## 1. 프로젝트 개요

- 이야기: 해외에서 김치가 그리워 할머니와 영상통화로 김치를 담그던 유학생(23세 여성)이 **잠깐 귀국**해, 비 오는 날 **가족(할머니·엄마·아빠·여동생)에게 부침개를 부쳐 준다.**
- 원본 게임: 친구가 만든 「할머니, 김치 어떻게 담가요?」(김장 시뮬레이터). 부침개는 그 **후속·자매 게임**입니다. 같은 세계관·말투(사투리 + "~도" 이어 말하기)를 따릅니다.
- 철학: **틀린 전은 없다.** 무엇을 넣어도 이름이 붙고 가족이 반응합니다. 단, 도감은 "만들면 생기는" 방식이 아니라 **정해진 레시피를 맞춰야 열리는** 방식입니다.
- 흐름 6단계: 재료 고르기 → 손질하기 → 반죽 만들기 → 굽기 → 담기 → 저녁 식탁. 각 단계에서 **이전 단계로 돌아갈 수 있어야** 합니다(구현됨).
- 시점: **1인칭**. 손은 보이지 않고 도구(칼, 뒤집개, 휘핑기 등)만 보입니다.
- 사용자가 원하는 최종 방향: **진짜 3D(Three.js)**, 사용자가 준 그림 스타일로 통일. 지금 배포된 건 2D입니다(아래 §6).

## 4. 단계별 구현 상태 [확실: 한 판 끝까지 돌려 오류 없음]

좌표는 논리 960×600 기준입니다. 상단 메뉴 0~60, 하단 대사·버튼 548~600.

1. **재료 고르기**: 8종(김치·부추·애호박·감자·오징어·양파·당근·청양고추) 중 최대 4개. 다시 누르면 뺌.
2. **손질하기**: 재료마다 썰기 방식 3개 중 선택. 방식마다 동작이 다름.
   - 탭형: 송송 9번 / 채썰기 12번 / 깍둑 6번 / 어슷 5번 / 동글 6번 / 링 5번 / 막썰기 4번
   - 꾹 누르기형: **다지기**(2.4초, 칼이 다다닥)
   - 재료 **그림 자체**가 격자로 갈라지고(`frags`), 방금 썬 조각이 손질 그릇·반죽 그릇에 들어감.
3. **반죽**: 가루 3종(부침가루=기본, 찹쌀가루=쫀득, 튀김가루=바삭) + 계란(0~2) + 소금·후추(0~3) + 물(되직/딱 좋음/묽음) + 꾹 눌러 섞기(휘핑기).
4. **굽기**: 기름 3종(올리브·포도씨·카놀라, 같은 병 다시 누르면 양 증가) + 키친타올(기름 고루 펴기·여분 닦기). 팬 톡=뒤집기, 팬 꾹=센불. 익는 정도 막대(덜/노릇/탐), 5단계 질감.
5. **담기**: 접시 더미 / 간장 종지(+청양고추 고명) / 통째 또는 **6조각**.
6. **식탁**: 가족 4명이 차례로 반응(말풍선+하트 4개), 결과 띠, 레시피 도감.
   - 도감: 10개 레시피(재료 + 각 재료 썰기 방식 + 가루/계란 조건). 못 연 칸은 그림자 + 힌트. 틀리면 "○○에 가까워요 (1/2)" 표시.

그 밖에: 인트로(6장면, 건너뛰기), 이전 단계 버튼, 로딩 게이트(모든 그림·글꼴을 불러온 뒤 시작), 소리(Web Audio 합성), 소리 끔 버튼.

### 누끼 도구 (`handoff-tools/`)
- `peel.py` : 가장자리의 배경색(회색/흰색) 픽셀을 반복해서 벗겨냄 (`char_*`, `prop_*`, `dish_*`에 적용)

- 각 스크립트는 `/tmp/...` 경로가 박혀 있으니 **경로를 고쳐서** 쓰세요.

## 6. 3D 전환 계획과 검증한 방법

사용자는 **.glb 없이도** 진짜 3D로 만들기를 원합니다(Meshy 유료, 무료 대안은 사용자가 번거로워함). **.glb는 필수가 아닙니다 [확실, 목업으로 확인]** — 아래 세 방식을 섞어 코드만으로 만들 수 있습니다.

1. **부엌·조리대·도마·후라이팬(12각)·믹싱볼·전 원반(12각)**: Three.js 기본 도형으로 코드 생성 + 검은 외곽선(뒤집은 확대 메시, `BackSide`) + `flatShading`. 김치 게임도 코드 로우폴리라 일관됩니다.
2. **재료·소품**: 사용자가 준 투명 PNG의 **외곽선(`contours.py` → `contours.json`)을 따서 `ExtrudeGeometry`로 두께 있는 3D 조각**을 만들고 그림을 앞면 텍스처로 입힘. 1인칭에서는 거의 정면이라 납작함이 눈에 띄지 않음.
3. **캐릭터**: 시트의 앞·뒤·좌·우·위 윤곽을 교차시켜 복셀 형태를 깎고(**visual hull**), 면마다 가장 알맞은 시점의 시트 그림을 투영해 입힘(`hull_character_viewer.html`, `hull_prep_views.py`).
   - 정면에서 ±10°까지는 시트와 거의 같음. **±20° 이상이면 옆모습 그림이 겹쳐 얼굴이 둘로 보임**(이 방식의 한계).
   - 삼각형이 인물당 약 12만 개(사양서 400~800 초과). 줄이면 윤곽이 더 각짐.
   - 걷거나 돌아서는 장면이 필요하면 **.glb가 필요**(그 경우만 사용자가 Hunyuan3D 2.1 등 무료 도구로 만들어 와야 함. Meshy 무료는 최신 모델 다운로드가 막혀 있음).
4. 전 굽기 5단계: 원반 윗면 텍스처를 단계별 PNG로 교체(이미 `st_*_1~5`가 있음). 6조각은 60° 부채꼴 6개를 독립 메시로.
- 3D 목업 장면: `mock3d_scene.html` (손질·굽기 2장면만 있음). `three.min.js`(r149, 로컬)와 `tex/`, `contours.json`, `views/`가 같은 폴더에 있어야 동작.

## 7. 알려진 문제와 한계

- 가족이 A자(팔 벌린) 자세로 고정되고 표정이 하나뿐(시트가 그래서). 반응에 따라 표정 바뀌는 건 들썩임만 있음. 팔 내린 자세·다른 표정 그림이 오면 교체.
- 사진 속 전은 종류(김치전·해물·부추·감자·호박)별 그림만 있어, 그 밖 조합(예: 당근+양파)은 가장 가까운 종류 그림을 씀. 고른 재료의 **썬 조각**은 반죽 그릇·손질 화면에만 보임(전 위에 덧그리던 건 사용자가 싫어해서 제거).
- Vercel에서 한글이 깨지면 `index.html`의 `<meta charset="utf-8">` 확인(넣어 둠).
- 새로고침할 때 대체 그림이 보였다 바뀌던 문제는 **로딩 게이트**로 고침. 느린 망에서 진행 막대가 도는 모습은 직접 못 봄 **[추측]**.
- 굽는 속도·가격 등 숫자, 가족 반응 규칙, 레시피 10개, 충청도 대사는 모두 **제가 만든 초안**이라 사용자 취향대로 계속 손봐야 함.

## 8. 검증하는 방법 (이 환경에서 쓰던 것)

1. 문법: `<script>` 내용을 뽑아 `node --check`
2. 실행: `python3 -m http.server 8791` 후 **Playwright(chromium)** 헤드리스로 화면 클릭을 흉내내며 한 판 끝까지 진행하고 스크린샷 저장.
   - 캔버스 좌표 변환: `x = box.x + X/960*box.width`
   - 소프트웨어 렌더링 3D: `--use-angle=swiftshader --enable-unsafe-swiftshader`
3. 스크린샷을 직접 보고 확인(겹침·깨짐·누끼 잔여물). 확대(`deviceScaleFactor:2`)로 선명도 확인.
4. 사용자에게는 **목업 이미지**를 먼저 보내고, 승인 후 `main`에 푸시.

1. 사용자에게 **승인 여부** 확인: 충청도 말투 / 썰기 이름 / 완성 전 그림 (`index.unreleased.html`). 승인되면 `main`에 푸시.
